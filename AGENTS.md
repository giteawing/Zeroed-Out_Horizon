# AGENTS.md — «Империя обнуленного горизонта»

Файл для будущих агентов и людей. Читать **перед** любой задачей, обновлять
**после** каждой. Техническое задание лежит в [`docs/TZ.md`](docs/TZ.md)
(исходный текст заказчика, перенесён из README при старте разработки).

---

## 1. Что это

Браузерная кликер-тапалка про нефтяную империю: тапаем по долоту, получаем
**нефтефаники (₦)**, покупаем политику/технику/роскошь, в конце — «Магистральный
Насос „Упырь-Абсолют"» и титры. Прохождение — **17–18 минут** реального времени,
это подтверждает автотест (`tests/balance.test.ts`).

Игра уже готова и работает. Ниже — как её запускать, как устроено и где
что менять.

## 2. Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # tsc --noEmit + vite build -> dist/
npm test           # юнит + DOM-тесты (vitest)
npm run test:e2e   # Playwright: только desktop (нужен браузер)
npm run art        # перегенерировать все SVG (иконки, фон, лого, финал)
npx tsx scripts/balance-report.ts   # отчёт по балансу
npx tsx scripts/auto-balance.ts     # подбор цен (без --write только отчёт)
```

## 3. Архитектура

```
src/
├─ content/           ← ВЕСЬ контент и весь баланс, кода не трогаем
│  ├─ config.json     параметры экономики, winCost, офлайн, мировые цены
│  ├─ upgrades.json   все покупки (145 штук) с типами и эффектами
│  ├─ texts.json      все тексты интерфейса, новости, достижения
│  ├─ achievements.json  правила достижений (id → условие)
│  └─ credits.txt     стихотворение для титров (пока заглушка)
├─ core/              ← логика без DOM, полностью покрыта тестами
│  ├─ types.ts        типы данных и событий
│  ├─ content.ts      загрузка + валидация JSON
│  ├─ economy.ts      формулы (цены, доход, налоги, победа), падение дебита
│  ├─ game.ts         движок: тап, покупки, тик, гэмблы, достижения
│  ├─ state.ts        создание/миграция/сериализация состояния, офлайн
│  ├─ storage.ts      localStorage-обёртка
│  ├─ assets.ts       пути к картинкам (работает в подпапке Pages)
│  ├─ format.ts       форматирование чисел/времени, интерполяция {key}
│  ├─ rng.ts          детерминированный ГПСЧ (mulberry32)
│  └─ simulator.ts    бот-игрок для теста баланса и подбора winCost
├─ ui/                ← только DOM, только данные из texts.json
│  ├─ dom.ts  texts.ts  hud.ts  shop.ts  drill.ts  news.ts
│  ├─ finale.ts  start.ts  settings.ts  wealth.ts
│  └─ dev.ts          инженерное меню 🛠 (деньги, мгновенный финал, все покупки)
├─ fx/particles.ts    canvas-частицы и всплывающие цифры (пул ≤ 40)
├─ audio/sound.ts     синтез звука на Web Audio API
├─ styles/base.css    вся палитра и адаптив
└─ main.ts            сборка UI + игровой цикл + сохранения
tests/                economy, game, state, content, balance, dom/, e2e/
scripts/              art-генераторы, balance-report, auto-balance
public/images/        111 иконок + bg.svg, logo.svg, drill.svg, finale.svg
```

**Главный принцип:** `core/` не знает про DOM, `ui/` не знает про формулы.
Экономика проверяется юнит-тестами и симулятором, интерфейс — DOM-тестами
(happy-dom) и Playwright.

## 4. Арт-гайд

Единый стиль (реализован в `scripts/lib/art.mjs`):

- **Пастель-нуар с золотом:** тёмный нефтяной фон, золото, малиновый, зелёный
  «деньги». Не больше 8 основных цветов, все — в CSS-переменных `:root`.
- **Обводка:** тёмная `#17110c`, толщина **3.4 px** (в 100×100 viewBox), round join/cap.
- **Заливки:** плоские + мягкий градиент и белый блик (`shine`).
- **Иконки:** квадратный `viewBox 0 0 100 100`, круглая подложка `#soft`.
  Читаются и в 64 px, и в 512 px (проверено рендером в обоих размерах).
- **Крупная графика:** `bg.svg` 1920×1080 (город, вышки, факел, пласт в разрезе),
  `logo.svg` 660×330, `drill.svg` 512×512, `finale.svg` 1024×1024.
- **Слои `drill.svg` для анимации (не переименовывать!):**
  `#cones` (шарошки, вращаются CSS-анимацией), `#btn-body` (корпус),
  `#splashes` (брызги), `#casing` (труба), `#rig` (мачта), `#strata` (пласт).

Палитра (CSS `:root` в `src/styles/base.css`):
`--ink #17110c`, `--gold #f2b430`, `--gold-light #ffd766`, `--crimson #b3243b`,
`--green #2f9e5f`, `--green-light #63d18d`, `--cream #fdf3dd`, `--steel #9aa4ad`.

## 5. Платформа (десктоп)

> **Мобильную поддержку убрали по решению заказчика.** Мобильные проекты
> в Playwright (iPhone 13, Pixel 7) и адаптивные медиазапросы под телефон
> удалены: игра делается и проверяется под десктоп. Ниже — что осталось
> полезным из «тач-гигиены».

- **Pointer Events:** тап — `pointerdown` (не `click`), мультитач работает:
  каждый палец = отдельный тап (`src/ui/drill.ts`).
- **CSS-защита:** `touch-action: manipulation`, `user-select: none`,
  `-webkit-tap-highlight-color: transparent` на сцене и кнопках.
- **Viewport:** `width=device-width, initial-scale=1, viewport-fit=cover`;
  отступы учитывают `env(safe-area-inset-*)`.
- **Раскладка:** два столбца. Слева большой `.stage__main` с магазином и
  вкладками, справа узкий `.stage__side`: таблица (`hud`), журнал (`oplog`),
  блок с долотом (`.stage__drill`). Порядок проверяет `tests/dom/layout.test.ts`.
- **Скролл:** прокручивается только список покупок; страница не скроллится.
- **Магазин показывает все покупки вкладки** (`Shop.defsFor`), закрытые — с
  классом `.card--locked`, неактивной кнопкой и красной причиной в
  `.card__lock` («Нужно заработать …», «Нужно: «…» (уровень N)»,
  «Нужно влияние не меньше …»). Ничего не прячем: игрок должен видеть цель.
- **Тач-цели:** минимум 44×44 px (проверяется e2e).
- **Производительность:** частицы/цифры ограничены пулом (40 и 18), анимации
  только `transform`/`opacity`, canvas в `devicePixelRatio ≤ 2`.
- **Фон/сохранение:** сохранение при `visibilitychange`, `pagehide`,
  `beforeunload` и раз в 10 с; при возврате начисляется офлайн-доход
  **с потолком 5 минут** (`config.offline.capSeconds`).
- **Клавиатура:** сцена и кнопки доступны с клавиатуры, есть `aria-*`.

## 6. Звук

Полностью синтезируется в `src/audio/sound.ts` (осцилляторы + шум + огибающие),
файлов нет — нет и вопросов с лицензиями.

| Звук | Метод | Где вызывается |
|---|---|---|
| Тап | `tap()` — 4 вариации высоты (740/820/690/880 Гц) | каждый `pointerdown` |
| Покупка | `purchase()` — кассовый «ча-чинг» | успешная покупка |
| Событие/кризис | `event(win)` — сирена вверх/вниз | гэмблы, ошибки |
| Достижение | `coin()` | новое достижение |
| Победа | `fanfare()` — фанфары | покупка «Упыря» |

Мобильные нюансы: `AudioContext` создаётся/возобновляется **только** внутри
первого пользовательского жеста (`sound.unlock()` в `onFirstTouch`), иначе
iOS/Safari молчит. Кнопка 🔊/🔇 — в топбаре и в настройках, состояние хранится
в сохранении.

## 7. Экономика в двух словах

```
tapValue   = (baseTap + Σ perTap·lvl) · Π(множители) · tapScale
oil/s      = Σ дебитов скважин / приз.секунд_в_сутках · Π(пассив) · autoDrill
gross/s    = Σ каналов · цена · priceFactor · priceMultiplier
net/s      = max(0, gross·(1 − taxRate) − salaries − officials)
cost       = baseCost · 1.15^lvl
```

- **Скважины — лотерея.** `config.oil.wells`: обычная 8–10 т/сут (70 %),
  хорошая 50–70 (25 %), уникальная 200–5000 (5 %). Дебит выпадает в
  `Game.drillWell()` и хранится в `state.wells` — не пересчитывается.
  `secondsPerDay = 1`: один игровой день = ровно одна реальная секунда
  (требование владельца). При большем значении честные «тонны в сутки»
  превращаются в 0,0001 т/с и игра стоит на месте.
- **Дебит падает со временем, но не сильно:** `wellDeclineFactor()` в
  `economy.ts` умножает добычу на `max(minFactor, 0.5^(playtimeMs/1000/halfLifeSeconds))`
  (`config.oil.wells.decline`: `minFactor 0.7`, `halfLifeSeconds 1800`).
  За партию теряется не больше 30 %. Падение заложено в `wellsTonnesPerSecond`
  и `wellsDailyTonnes`, поэтому HUD и экономика всегда согласованы.
- **Налог зависит ТОЛЬКО от влияния и `taxCut`-покупок:**
  `taxRateOf()` = `baseRate − влияние·influenceDrop − послабления`, пол
  `minRate`. Временные буффы (`TaxBuff`) на ставку больше не влияют —
  иначе налог «случайно прыгает». Это закреплено тестом.
- **Контракты измеряются в тысячах тонн** (`baseRate = 5000` т/с):
  безлимитный канал не должен быть узким горлышком.
- Расходы снижаются `costCut` и растут от найма персонала/чиновников.
- Разовые выплаты и периодика считаются как «секунды текущего темпа»
  (см. `eventPayout` в `economy.ts`) — поэтому они не устаревают по мере роста.
- **`winCost` = 8,0e10 ₦** — подобран симулятором под 15–20 минут
  (14,7 / 17,6 / 17,6 мин на 4 / 5 / 6 тапах в секунду). Тот же порог лежит
  в `upgrades.json` у `win_pump.baseCost` — правьте оба.

## 8. Решения (приняты агентом самостоятельно)

1. **README заменён.** Исходное ТЗ перенесено в `docs/TZ.md` без изменений.
   README теперь — инструкция по запуску и замене контента (требование ТЗ §9.1).
2. **Стек оставлен из ТЗ** (Vite + TS + Vitest + Playwright): это самый
   отработанный harness, отдельный фреймворк не нужен.
3. **E2E-замена.** В песочнице агента браузеры Playwright не скачиваются
   (CDN заблокирован). Поэтому дополнительно написан **DOM-смоук-тест на
   happy-dom** (`tests/dom/app.test.ts`), который поднимает настоящий `main.ts`
   и проверяет тапы/покупки/финал. Playwright-тесты лежат в `tests/e2e` и
   запускаются в CI.
4. **Покупки-действия (`repeatable`).** «Попросить монет», «Швырнуть
   подрядчика» и т.п. ограничены **перезарядкой**, а не уровнем. Иначе после
   первой покупки кнопка навсегда стала бы «Максимум». Флаг `repeatable: true`
   в `upgrades.json`.
5. **Улучшены 4 события:** «Пихнуть нефть заграницу» зависит от мировой цены
   (копится ×0.7…×1.3) и усиливается морским терминалом; сенат даёт временный
   налоговый буфф; кризисы — гэмблы с шансом и таймером.
6. **Баланс делался не на глаз:** `scripts/auto-balance.ts` подгоняет цены под
   целевой темп, затем `scripts/balance-report.ts` проверяет три профиля
   игрока (4/5/6 тапов в секунду). Глубина прокачки (maxLevel) ограничена,
   иначе множители «стекаются» и доход улетает в астрономию.
7. **Графика генерируется скриптами** (`npm run art`) — так стиль остаётся
   единым, а файлы можно править руками: тест `content.test.ts` проверит,
   что у каждой покупки есть иконка.
8. **Шрифты:** системные (`Georgia` для заголовков, `Trebuchet MS`/`system-ui`
   для текста) — никаких внешних запросов, игра работает офлайн.
9. **Формат чисел:** русские сокращения «тыс. / млн / млрд / трлн», запятая
   как десятичный разделитель.
10. **Ужатие winCost>обучения:** финальная покупка требует не только денег, но
    и уровней `t_pump4` (Насос-Гигант, 5) и `t_smart` (Умная скважина, 3) —
    чтобы финал не покупался «случайно» в начале.

## 9. Известные проблемы и ограничения

- **Playwright браузеры в песочнице не ставятся** (см. п.3 решений). В CI
  работают; локально нужен `npx playwright install chromium`.
- `credits.txt` содержит заглушку. Игра показывает «Здесь будет стихотворение.»
  — это ожидаемое поведение по ТЗ §7.4. Текст должен положить владелец.
- Симулятор баланса считает по своей эвристике «самое выгодное». Живой игрок
  может играть медленнее — нижняя граница 12 минут в тесте это учитывает.
- Очень дешёвые покупки (70–100 ₦) видны в магазине сразу; дорогие
  открываются по «накопленному заработку», а не по текущему балансу.

## 11. Подсказки будущим агентам

- **Меняешь цену/эффект — прогони `npm test`**: тест баланса упадёт, если
  прохождение выйдет за 12–25 минут.
- **Добавляешь покупку:** только в `upgrades.json` + иконку в
  `public/images/icons/<icon>.svg` (или через `npm run art`). Код трогать не надо.
- **Добавляешь новый тип эффекта:** `types.ts` → `economy.ts`
  (`computeDerived`) → `simulator.ts` (`estimatedGain`) → подпись в
  `shop.ts` (`describeEffect`) → тест в `economy.test.ts`. Пять мест, не больше.
- **Не хардкодь русские строки в `ui/`** — это ловит тест
  `content.test.ts > в коде интерфейса нет зашитых русских строк`.
- **Не убирай `id` слоёв в `drill.svg`** — на них держится CSS-анимация бурения.
- **Не прячь заблокированные покупки** — они должны быть видны с причиной
  блокировки (требование владельца, этап 4).
- **Инженерное меню (`src/ui/dev.ts`)** — не отладочная ветка, а часть игры:
  кнопки «+1 трлн», «Купить «Упырь-Абсолют»», «Открыть все покупки». Оно
  пишет в сейв через публичные `Game.addCoins()`/`Game.forceWin()`; не
  удаляйте эти методы — на них держатся e2e и ручная проверка финала.
- **Скважины не «провайдер добычи по уровням»**: `type: 'well'` не накапливает
  добычу уровнями, а бурит новую скважину при каждой покупке. Добавляя такую
  покупку, добавь её id в `WELL_UPGRADE_IDS` в `game.ts`.
- **Меняешь конфиг в тесте** — вызывай `game.invalidate()`, иначе кеш
  производных покажет старые числа.
- **Надписи не обрезаем:** никаких `-webkit-line-clamp` и `text-overflow:
  ellipsis` в карточках, журнале и новостях — заказчик просил, чтобы текст
  читался целиком.
- Перед коммитом: `npm run build && npm test`.
