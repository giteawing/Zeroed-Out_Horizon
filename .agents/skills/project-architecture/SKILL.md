# Архитектура проекта

## Карта модулей

```text
src/
  content/       config.json, upgrades.json, texts.json, achievements.json, credits.txt
  core/          types, content loader, economy, game engine, state, storage, simulator, RNG
  ui/            DOM-компоненты: HUD, магазин, бурение, новости, финал, настройки
  fx/            canvas-частицы и всплывающие значения
  audio/         Web Audio API
  styles/        основная таблица стилей
  main.ts        создание приложения и связывание слоёв
tests/
  *.test.ts      ядро, состояние, контент, баланс и регрессии
  dom/           DOM-поведение на happy-dom
  e2e/           пользовательские сценарии Playwright
scripts/         SVG-генерация и инструменты балансировки
public/images/   изображения и иконки
```

## Направление зависимостей

- `core/` — чистая игровая модель. Не импортирует `document`, `window`,
  HTML-элементы или классы из `ui/`.
- `ui/` получает данные и методы игрового ядра и отвечает за отображение,
  события и доступность. Не вычисляет самостоятельно цены, доход, налоги,
  ограничения каналов или условия победы.
- `main.ts` — composition root: загружает контент, поднимает состояние и
  экземпляр `Game`, соединяет DOM, звук, сохранение и игровой цикл.
- `src/content/*.json` — изменяемые данные, а не место для дублирования
  алгоритмов. Валидация и типизация выполняются через `core/content.ts`.

## Типовой путь данных

1. `loadContent()` читает и валидирует JSON-файлы контента.
2. `createInitialState()` создаёт состояние по конфигурации; при загрузке
   `normalizeState()` сливает сохранение с актуальными дефолтами и удаляет
   неизвестные/недопустимые значения.
3. `Game` выполняет действия, тики, покупки, события, продажи и расчёты.
4. `computeDerived()` в `economy.ts` возвращает производные показатели,
   используемые движком, симулятором и UI.
5. UI отображает полученные данные; сохранение обслуживает `storage.ts` и
   интеграция в `main.ts`.

## Где менять разные вещи

| Задача | Основное место | Обязательная проверка |
|---|---|---|
| Цена/эффект покупки | `src/content/upgrades.json` | экономика + баланс |
| Параметр экономики | `src/content/config.json` + `economy.ts` | economy/regression/balance |
| Новый тип эффекта | `types.ts`, `economy.ts`, `game.ts`, `simulator.ts`, UI-магазин | unit + regression + balance |
| Сохранение нового поля | `types.ts`, `state.ts`, `game.ts` | state migration + serialization |
| Подпись интерфейса | `texts.json` и компонент UI | content + DOM/E2E |
| Вёрстка | `src/ui/`, `src/styles/base.css` | DOM + E2E |
| Изображения | `public/images/`, `scripts/` | content tests + визуальная проверка |

## Правила изменений

- Сначала найди все места чтения/записи поля или эффекта поиском по идентификатору.
- Не вводи альтернативное представление уже существующего свойства без причины.
- Новое поле `GameState` должно иметь безопасное значение в
  `createInitialState()` и нормализацию в `normalizeState()`. Добавь тесты
  для старого сейва без поля, неверного значения и round-trip сериализации.
- При несовместимом изменении формата оцени необходимость увеличить
  `SAVE_VERSION` и реализуй миграцию. Не повышай версию автоматически при
  каждом добавленном необязательном поле.
- Сохранение — пользовательские данные. Не удаляй и не сбрасывай сейвы в
  production-пути ради удобства теста.
- При добавлении эффекта обнови определения типов, реальную механику, оценку
  эффекта симулятором, описание в магазине и проверки. Отсутствие одного из
  звеньев приводит к расхождению между игрой и ботом.
- Не храни дублирующие вычисляемые значения в состоянии, если их можно
  безопасно получить из первичных данных. Если кэш необходим, обеспечь
  инвалидирование после изменения конфигурации/состояния.
- `docs/TZ.md` — исторический документ. Текущее desktop-only решение и
  фактические границы модулей описаны в коде и корневом `AGENTS.md`.
