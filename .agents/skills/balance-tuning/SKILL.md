# Баланс и симулятор

## Цель

Целевой темп прохождения — примерно 15–20 минут. Тест допускает более широкий
коридор 12–25 минут, чтобы учитывать различия профилей. Не подгоняй цифры под
один удобный прогон: проверяются четыре профиля игрока.

## Инструменты и профили

- `src/core/simulator.ts` — детерминированный бот; использует `Game` и
  реальные правила экономики. Сохраняй детерминированность и seed.
- Профилей четыре, список один — `BALANCE_PROFILES` в
  `src/core/simulator.ts`; его используют и тесты, и отчёт:
  - быстрый экспорт: ожидание выгодной котировки до 20 с;
  - сбалансированная логистика: ожидание до 40 с;
  - терпеливый экспорт: ожидание до 60 с;
  - оптимизатор: отдельная стратегия выбора покупок и повторяемых действий.
- `tests/balance-profiles.test.ts` — первые два профиля,
  `tests/balance-profiles-extra.test.ts` — два остальных. Каждый профиль
  прогоняется ровно один раз (следит `tests/harness.test.ts`).
- `tests/balance-pace.test.ts` — темп 15–20 минут и рост дохода;
  `tests/balance-content.test.ts` — выкуп контента;
  `tests/balance-growth.test.ts` — рост империи без финала.
  Файлы разделены, чтобы каждый укладывался в 60 секунд; новую длинную
  симуляцию клади в отдельный `tests/balance-*.test.ts`.
- `scripts/balance-report.ts` — сравнивает кандидаты winCost на этих профилях.
- `scripts/auto-balance.ts` — экспериментально меняет базовые цены покупок,
  используя симулятор.

Команды:

```bash
npm test
npm run balance        # все tests/balance-*.test.ts
npm run balance:report
npm run balance:auto
```

Первый запуск auto-balance — только отчёт. Он не должен менять файлы.

## Опасная операция записи

`--write` у `auto-balance.ts`, `tune-2d.ts` и `tune-scale.ts` требует
дополнительного `--i-know`. Даже с этим флагом запись запускай только по
явной задаче владельца; сначала сохрани исходные JSON и проверь diff.
`migrate-oil-model.ts` отключён как устаревший и перезаписывающий контент.
Скрипт сериализует список покупок заново: внимательно проверь весь diff,
включая комментарии, порядок, закреплённые цены и специальные типы покупок.

## Протокол изменения баланса

1. Зафиксируй исходные показатели: текущий commit, winCost, четыре профиля,
   число покупок, общее заработанное и список купленных ID.
2. Меняй один логический параметр за итерацию. Не меняй одновременно темп
   добычи, цену продажи, налоги и все цены покупок — иначе причину эффекта
   невозможно определить.
3. Для правок стоимости проверь `costFor()`, рост цены и скидки, а также
   пакетные покупки и ограничения `maxLevel`.
4. Проверь, что симулятор учитывает дебит скважин, производственные
   множители, физические ограничения маршрутов, перезарядки и реальные условия
   разблокировки. Не упрощай механику в боте так, чтобы он играл в другую игру.
5. Сверь `config.winCost` и `win_pump.baseCost`; если меняется одно, второе
   должно оставаться согласованным.
6. Запусти `npm run balance:report`, затем `npm run balance` (все файлы
   профилей и прогрессии), `npm test` и `npm run build`.
7. В отчёте укажи не только минуты, но и количество покупок, добычу,
   заработанные деньги и отклонения между профилями. Если целевой темп нарушен,
   не маскируй это ослаблением теста.

## Текущая исходная точка

В текущей конфигурации `config.winCost = 2.5e24`, цена `win_pump` должна
совпадать с ней. Это **номинал**: все цены выше `currencyCostCurve.anchor`
(1e5) сжимаются по корню (`exponent = 0.5`), поэтому игрок платит за финал
`adjustCurrencyCost(2.5e24) = 5e14` (500 трлн ₦). Подбирая цены, сравнивай
доход игрока с ценой после кривой (`costFor`, `winCostOf`), а не с числом из
JSON. Целевой темп обычного профиля — 15–20 минут; остальные профили
контролируются в диапазоне 12–25 минут. Это baseline, а не гарантия после
изменения механики: всегда запускай свежий отчёт на текущем HEAD.
