# Баланс и симулятор

## Цель

Целевой темп прохождения — примерно 15–20 минут. Тест допускает более широкий
коридор 12–25 минут, чтобы учитывать различия профилей. Не подгоняй цифры под
один удобный прогон: проверяются три профиля игрока.

## Инструменты и профили

- `src/core/simulator.ts` — детерминированный бот; использует `Game` и
  реальные правила экономики. Сохраняй детерминированность и seed.
- `tests/balance-profiles.test.ts` — три контрольных профиля прохождения.
- `tests/balance.test.ts` — темп, выкуп контента и устойчивость роста экономики.
- `scripts/balance-report.ts` — сравнивает кандидаты winCost с профилями:
  - ленивый: 4 тапа/с, diligence 0.70, терпение экспорта 20 с;
  - обычный: 5 тапов/с, diligence 0.85, терпение 40 с;
  - упорный: 6 тапов/с, diligence 0.95, терпение 60 с.
- `scripts/auto-balance.ts` — экспериментально меняет базовые цены покупок,
  используя симулятор.

Команды:

```bash
npm test
npm run balance:report
npm run balance:auto
```

Первый запуск auto-balance — только отчёт. Он не должен менять файлы.

## Опасная операция записи

`npx tsx scripts/auto-balance.ts --write` записывает новые цены сразу в
`src/content/upgrades.json` и `src/content/config.json`. Запускай её только
при явной задаче на перебалансировку или после согласования владельца.
Скрипт сериализует список покупок заново: внимательно проверь весь diff,
включая комментарии, порядок, закреплённые цены и специальные типы покупок.

## Протокол изменения баланса

1. Зафиксируй исходные показатели: текущий commit, winCost, три профиля,
   число покупок, общее заработанное и список купленных ID.
2. Меняй один логический параметр за итерацию. Не меняй одновременно темп
   добычи, цену продажи, налоги и все цены покупок — иначе причину эффекта
   невозможно определить.
3. Для правок стоимости проверь `costFor()`, рост цены и скидки, а также
   пакетные покупки и ограничения `maxLevel`.
4. Проверь, что симулятор учитывает влияние, scope-множители, ручные тапы,
   перезарядки и реальные условия разблокировки. Не упрощай механику в боте
   так, чтобы он играл в другую игру.
5. Сверь `config.winCost` и `win_pump.baseCost`; если меняется одно, второе
   должно оставаться согласованным.
6. Запусти `npm run balance:report`, затем `npm run balance` (оба файла
   профилей/прогрессии), `npm test` и `npm run build`.
7. В отчёте укажи не только минуты, но и покупки/тапы/деньги и отклонения
   между профилями. Если целевой темп нарушен, не маскируй это ослаблением
   теста.

## Текущая исходная точка

В актуальной конфигурации на момент последней калибровки:
`config.winCost = 6e16`, цена `win_pump` совпадает. В отчёте
`balance-report.ts` обычные профили проходили примерно за 18–19 минут.
Это baseline, а не гарантия после изменения механики: всегда запускай свежий
отчёт на текущем HEAD.
