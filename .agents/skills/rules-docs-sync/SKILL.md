# Правила, тексты и документы меняются вместе с механикой

Ревизия нашла десяток расхождений «написано одно — игра делает другое»:
правила называли контракт безлимитным, ставка обещала ×10 при множителе 2,
README описывал симметричный коридор цены. Причина одна: механику меняли, а
объяснения оставались прежними. Объяснений у игры много, и все они должны
меняться в том же коммите, что и код.

## Где игре объясняют, как она работает

| Что | Где лежит | Что сверяет с игрой |
|---|---|---|
| Окно «Правила игры» | `src/ui/rules.ts`, раздел `rules` в `src/content/texts.json` | `tests/dom/rules.test.ts` |
| Описание карточки | `description` в `src/content/upgrades.json` | `tests/rules-consistency.test.ts` |
| Строка эффекта на карточке | `src/ui/effect-line.ts`, раздел `shop` текстов | `tests/effect-line.test.ts` |
| Поля `effect` и кто их читает | `EFFECT_FIELDS` в `src/core/content.ts`, таблица в `docs/ECONOMY.md` | `tests/effect-fields.test.ts`, `tests/harness.test.ts` |
| Панель империи | `src/ui/hud.ts`, раздел `hud` текстов | `tests/dom/hud.test.ts` |
| Достижения | `src/content/achievements.json` | `tests/achievements.test.ts` |
| Лента новостей | `src/ui/news.ts`, раздел `news` текстов | `tests/dom/news.test.ts` |
| README, раздел «Как играть» | `README.md` | `tests/harness.test.ts`, `tests/rules-consistency.test.ts` |
| Устройство экономики для разработчика | `docs/ECONOMY.md`, навыки `economy-accounting` и `balance-tuning` | `tests/harness.test.ts` |
| Любой текст интерфейса | `src/content/texts.json` | `tests/texts-usage.test.ts` |

## Порядок работы

1. Найди поиском по идентификатору (поле конфига, id покупки, имя функции)
   все строки таблицы, которые упоминают меняемую механику. Число из
   `config.json` ищи и как число, и по смыслу: «5 минут», «28 %», «×25,8».
2. Поменяй код и объяснения одним коммитом. Правка «только код, тексты
   потом» — это и есть расхождение.
3. Запусти тесты из третьего столбца. Упавший тест сверки — не помеха, а
   сообщение: объяснение устарело. Чини объяснение, а не тест.
4. Изменились числа баланса — дальше по навыку `balance-tuning`
   (`npm run balance:report`, `npm run balance`).

## Числа в текстах — из данных

- В шаблонах правил чисел нет: только подстановки `{имя}`, которые заполняет
  `src/ui/rules.ts` из конфигурации и ядра. Число, вписанное руками, тест
  отклонит. Числительное («один раз», «трёх направлений») сверяется с
  данными там же, в `tests/dom/rules.test.ts`.
- Число в описании карточки должно выводиться из её `effect`, `unlockAt` или
  конфига: таблица `NUMERIC_FACTS` в `tests/rules-consistency.test.ts`.
  Множитель показывает строка эффекта; описание его словами не называет.
- Числа в README и `docs/ECONOMY.md` сверяет `tests/harness.test.ts`: он
  считает значение из данных и ищет его в тексте. Новое число в этих
  документах — новая проверка там же.
- Дробные числа в текстах — через запятую.

## Обещания в текстах — подтверждены полями

- Слово-обещание требует поля: «влияние» — `effect.influence` или условие по
  влиянию, «покупается один раз» — один уровень без перезарядки; периодическая
  покупка описана как выплата, а не как добыча; ставка — как ставка, с
  проигрышем. Проверки — в `tests/rules-consistency.test.ts`; добавил новое
  обещание — добавь проверку.
- Новое поле `effect` нельзя просто дописать в JSON: загрузчик отклонит поле,
  которого нет в `EFFECT_FIELDS` для этого типа покупки. Полю нужны читатель
  в ядре, оценка в симуляторе, строка эффекта и строка в таблице
  `docs/ECONOMY.md`. Нет читателя — нет поля.

## Чего тесты не видят

Тесты сверяют числа и слова-обещания, но не смысл фразы. После правки
механики перечитай изменённый абзац правил и README целиком и сравни с
кодом: порядок действий, условия, исключения. Если сверить не удалось —
напиши об этом в отчёте, а не «правила обновлены».
